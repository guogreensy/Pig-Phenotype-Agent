# 学习路线：怎么读懂这个工程

给第一次接触本工程的人（尤其是研一同学）的阅读指南。目标不是"读完所有代码"，而是**先建立直觉，再逐层深入**。

---

## 一、先建立全局印象：这是"两层楼"

```
用户提问
   │
   ▼
┌─────────────────────────────────────────┐
│ 上层：对话助手（本阶段重点）              │
│  会规划：先查数据？先查文献？还是先看图？  │
└──────────────┬──────────────────────────┘
               │ 调用工具
┌──────────────▼──────────────────────────┐
│ 下层：三样能力                            │
│   查数据（模拟养殖场）                     │
│   查文献（20 篇 / 943 片段）               │
│   看图  ← 阶段一的姿态识别，退居为一个工具  │
└─────────────────────────────────────────┘
```

一句话：**阶段一证明"看图不太准"，阶段二让模型学会"不确定就去查"，而不是硬编。**

四类目录的分工要记牢：

| 目录 | 角色 | 是否参与运行 |
|---|---|---|
| `src/` | 系统本体 | ✅ 参与 |
| `scripts/` | 开发期工具（建库、跑实验、出图） | ❌ 不参与 |
| `data/` | 原料（样本图、知识库、题集） | 被读取 |
| `results/` | 证据（90 次对话、指标、图表） | 被写入 |

## 二、一次提问的完整旅程

从你在网页上敲下问题，到看到带 `[1] [2]` 的回答，经过这些地方：

| 步骤 | 发生什么 | 代码位置 |
|---|---|---|
| 1 | 前端发 POST 到 `/api/agent` | `src/webapp.py`（前端 JS + `AgentHandler`） |
| 2 | 拼系统提示词：7 条规矩 + 8 个工具的说明书 | `src/agent/planner.py` |
| 3 | 问模型：要工具吗？ | `src/agent/llm_client.py` |
| 4 | 要工具 → 查参数 → 执行 → 结果塞回消息 | `src/tools/registry.py` + `src/agent/executor.py` |
| 5 | 模型不再要工具 → 得到最终文本 | `src/agent/executor.py` |
| 6 | 抽引用、编编号、判来源（是否用了模拟数据） | `src/agent/report.py` |
| 7 | 拼成 JSON 返回页面 | `src/webapp.py` |

**读懂这张表，你就读懂了这个系统。**

## 三、六步阅读路线

### 第 0 步：先玩，别急着读（30 分钟）

```bat
启动助手.bat
```

问三个问题，每次把回答下面的"工具轨迹"展开：

1. `P2-007 最近 7 天的平均采食量是多少？` —— 看它调 `aggregate_metric`
2. `姿态识别常用哪些深度学习方法？` —— 看它调 `search_knowledge`，可能再调 `fetch_passage`
3. `P5 栏的采食量怎么样？` —— 看工具返回"没有这个栏位"，模型如实转述

**展开的表格里，`tool` 是工具名，`args` 是模型给的参数，`ok` 是成功与否。** 这三列就是整个系统的行为记录。

### 第 1 步：两个短文件（共 106 行）

| 文件 | 行数 | 看什么 |
|---|---:|---|
| `src/agent/planner.py` | 81 | 提示词是怎么拼出来的；七条规矩各防什么坑 |
| `src/tools/builder.py` | 25 | 工具是怎么注册进注册表的（装配清单） |

重点看 `planner.py` 里的规矩，每一条都对应一次真实翻车：模型把不同论文的结论合并、把 1.626 心算成 1.69、把模拟数据说成真数据。

### 第 2 步：看心脏（270 行）

`src/agent/executor.py` —— **这是全工程最值得逐行读的文件。**

```
while 还有步数:
    问模型 → 有 tool_calls 就执行 → 结果塞回去
    没有 tool_calls 就收工
步数用完 → 去掉工具再问一次（强制收尾）
```

读的时候盯住三个问题：预算在哪减、重复调用怎么拦、工具报错怎么回填。

### 第 3 步：查数是怎么算的

`src/tools/mock_data.py`（221 行）→ `src/tools/data_tools.py`（286 行）。

先看 `mock_data.py`：固定种子造出 4 栏 48 头 30 天数据，还埋了三个"剧情"（P3 热应激、P2-007 采食下降、P4-003 活动下降）。这些剧情就是实验题目的标准答案来源。

再看 `data_tools.py`：一个工具如何"过滤 → 分组 → 求均值 → 加免责声明"。

### 第 4 步：查文献是怎么找的

按这个顺序，从简到繁：

| 顺序 | 文件 | 行数 | 一句话 |
|---:|---|---:|---|
| 1 | `src/rag/corpus.py` | 407 | 抓网页、洗正文、切片段（切不好后面全白搭） |
| 2 | `src/rag/lexical.py` | 152 | 字符 n-gram 的 TF-IDF（最简的一路） |
| 3 | `src/rag/dense.py` | 301 | 调 embedding 存成矩阵，点积算相似度 |
| 4 | `src/rag/retrieve.py` | 264 | 两路结果加权合并（RRF），出错转词法 |

核心思想一句话：**一路按字面匹配、一路按语义匹配，把两个排名加权融合；稠密挂了就用词法兜底。**

### 第 5 步：界面（最后看，只看三处）

`src/webapp.py` 731 行，但只需要看：

1. 路由表（`/`、`/api/health`、`/api/predict`、`/api/agent`）
2. `AgentHandler.post`：怎么校验参数、怎么加锁防并发、怎么把耗时任务丢进线程池
3. 前端 `fetch('/api/agent')` 那几行

其余是 CSS 和 HTML，不用读。

### 第 6 步（可选）：实验是怎么跑出来的

`scripts/run_agent_experiment.py`（怎么跑 90 次）→ `scripts/evaluate_agent.py`（怎么判对错）。

这里能看到一个关键设计：**标准答案不是工具算的，是从原始数据独立算的**，否则就是自己给自己判卷。

## 四、三个自测问题

答得上来，说明你真读懂了。

**Q1：前端传 `max_steps=0`，系统最终用几步？夹取写在哪？**

<details>
<summary>答案</summary>

用 1 步。`src/webapp.py` 的 `AgentHandler` 里区分了"没传"和"传了 0"：没传用默认 6，传了就 `max(1, min(8, n))`。早期版本用 `n or default`，导致 0 被静默改成 6，测试抓到了这个 bug。
</details>

**Q2：embedding 接口挂了，用户还能查到东西吗？**

<details>
<summary>答案</summary>

能，但不保证相关性。`retrieve.py` 在 `auto` 模式下捕获稠密路径的任何异常，转走词法索引，并带上 `degraded=true` 与原因。报告层会把这次对话标记为"存在降级"。实验期共发生 21 次，没有一次中断对话。
</details>

**Q3：回答末尾的 `[1] [2]` 是谁生成的？为什么不让模型自己写？**

<details>
<summary>答案</summary>

是 `src/agent/report.py` 生成的，按检索证据首次出现的顺序编号。不让模型写，是因为模型会编造参考文献（阶段一就出现过"三个查不到的论文标题"），而程序只认工具真正返回过的片段，编号一定能点回原文。
</details>

## 五、三个常见疑问

**为什么非要工具？模型自己算不行吗？**
试过。模型把 7 条记录的平均值心算成 1.69，正确值是 1.626。数字一错，后面所有分析都白搭。工具算的是同一份数据，不会错。

**为什么不把知识全塞进提示词？**
943 个片段塞不进上下文；而且模型对"塞进去的长文"仍然会记错、串台。检索的价值是**每次只给它最相关的几段**。

**降级了为什么不直接报错？**
用户要的是答案，不是错误码。降级会明确标注"本次检索质量下降"，让用户自己判断可信度——**比静默失败或假装正常都好**。

## 六、动手练习（由易到难）

1. **改一个参数**：把 `src/tools/data_tools.py` 里 `query_pig_records` 的默认 `limit` 从 50 改成 20，重启服务，观察回答里的明细条数变化。
2. **加一道题**：在 `scripts/build_questions.py` 里加一个数据题（比如"P4 栏平均体重"），重新生成题集，只跑这一题：`python scripts/run_agent_experiment.py --ids D11 --conditions full`。
3. **看一次翻车**：把 `.env` 里的 `PIG_TOOL_MODEL` 改成一个不支持 tool_calls 的模型，启动后提问，观察系统如何报错——这能让你理解"为什么视觉模型不能兼做工具调用"。
4. **读懂一个判定**：打开 `results/metrics/agent_per_question.csv`，找 `D6` 那一行，对照实验报告 6.5 节，看"检索结果覆盖提示词"是怎么被发现的。

## 七、推荐阅读顺序（时间预算）

| 时间 | 做什么 |
|---|---|
| 第 1 小时 | 跑起来，问 3 个问题，展开工具轨迹 |
| 第 2 小时 | 读 `planner.py` + `executor.py`（共 351 行） |
| 第 3–4 小时 | 读 `mock_data.py` + `data_tools.py`，理解"工具怎么算数" |
| 第 5–6 小时 | 读 rag 四件套，理解"两路召回 + 融合" |
| 第 7 小时 | 读 `report.py` + `webapp.py` 的三个关键处 |
| 之后 | 读两份报告，把代码与实验结论对上 |

**不要**一上来读 `webapp.py`（731 行，一大半是样式），也**不要**先读 `corpus.py`（407 行，全是清洗细节，容易劝退）。
