# 技术报告：基于多模态大语言模型的猪只姿态识别与可见体态描述系统
版本：2026-10-19 运行环境：Windows + Python 3.9.25（conda data_science 环境）
说明：本报告描述已实现并已测试的系统。涉及模型能力与实验结论的部分见
实验报告，其中未运行的部分明确标注「待实验」。
## 1. 项目背景与需求分析
## 1.1 背景
猪只姿态（站立、侧卧、俯卧、坐姿）是养殖场巡检中可直接观察的表型信息，
也是行为监测与福利评估的基础。传统方案需要训练专用视觉模型；而多模态大模型
（VLM）提供了"零样本/少样本 + 语义解释"的替代路径。
本项目定位为应用层原型：不做模型训练或微调，而是围绕云端 VLM API 构建
一条可复用、可评测的流水线，并用对照实验回答"提示词设计能带来多少收益"。

## 2. 系统总体架构
数据流：图片 → 校验 → EXIF 纠正 → 长边缩放 512px → JPEG 重编码 →
Base64 Data URI → chat/completions → 原始文本 → 解析 → Schema 校验 →
逐条记录 CSV → 指标 → 图表/报告。
## 3. 技术选型与理由
| 层 | 选型 | 理由 | 与需求建议的差异 |
|---|---|---|---|
| 语言 | Python 3.9.25 | 本机现成环境，零安装 | 需求建议 3.10+，如实记录差异 |
| Web | tornado 6.5.1 | 已随 Jupyter 安装；支持 multipart 与异步 | 用自写单页替代 Gradio |
| 测试 | unittest（标准库） | 零安装，能力等价 | 替代 pytest |
| 配置 | 自写 .env 解析（30 行） | 零安装 | 替代 python-dotenv |
| 图像 | Pillow 11.3.0 | EXIF、缩放、裁剪齐备 | — |
| 数据 | pandas 2.3.3 / numpy | 表格与数值 | — |
| 指标 | 纯 Python 手算 + sklearn 交叉核对 | 口径可控、可审计 | 需求建议 sklearn，本项目把它当"第二实现" |
| 图表 | matplotlib 3.9.2（Agg + 微软雅黑） | 中文无豆腐块 | — |
| 模型 | 智谱 glm-4.6v-flash（免费） | 无需充值，降低课程成本 | 需求建议 Qwen-VL/GLM，二者均实现 |
实际使用的模型：最终实验采用 glm-4.1v-thinking-flash（同样免费）。
原因是实测发现 glm-4.6v-flash 在当前网络下限流严重（模型级拥堵，单次验证 8 张仅 3 张成功、
即使退避 137 秒仍会失败），而 glm-4.1v-thinking-flash 在同样条件下 8/8 成功、
正式实验 600 次调用零失败。三组提示词全程使用同一个模型，控制变量成立。
为什么不用 Gradio：gradio==4.44.1 要求 pillow<11，会把环境中的
pillow 11.3.0 降级，影响同环境下其它项目；新版 gradio 需要 Python ≥3.10。
需求说明书明确允许"若某个库与当前 Python 环境不兼容，应选择简单、稳定的替代方案，
并在文档中说明"。因此改用 tornado，接口层与 UI 层解耦，未来替换成本低。
## 4. 核心模块设计
## 4.1 config.py —— 配置
.env 自解析：忽略注释/空行、支持 export 、剥除成对引号；
优先级：进程环境变量 > .env > 默认值；
密钥缺失时抛 MissingAPIKeyError，消息为可操作的中文提示；
数值型配置非法时抛 ConfigError 并指出变量名。
## 4.2 src/schema.py —— 结果契约
| 字段 | 类型 | 约束 |
|---|---|---|
| posture | enum | standing / lyinglateral / lyingother / sitting / unknown |
| description | string | 非空；>500 字仅告警不判非法 |
| uncertain | bool | 必须为布尔（接受 "true"/"false" 字符串并记录） |
| uncertainty_reason | string \| null | 类型不符判非法 |
一致性规则：posture=unknown 且 uncertain=false → 记 warning。
中文同义词（"侧卧""站立""趴卧"…）与混合写法（standing（站立））都能归一化。
数据集 5 类 → 4 类的映射集中在此模块，避免各处硬编码。
## 4.3 src/output_parser.py —— 解析与降级
解析前先做推理过程剥离：本实验使用的思考型模型会输出
<think>推理</think><answer>结论</answer>，推理里常出现与结论相反或半截的类别词。
因此先移除 <think> 块，若存在 <answer> 则只解析其内容，避免推理污染结果。
在此基础上级联解析：
1. json.loads 直接解析；
2. 剥离 围栏 → 括号配对扫描（正确处理字符串内的 {}` 与转义引号）→ 再解析；
3. 轻量修补（智能引号、尾随逗号、Python 字面量、单引号键值）→ 再解析；
4. 正则逐字段抽取，标记 json_valid=false；
5. 自由文本抽取：从自然语言回答中抄出出现的规范类别词（A/B 组即此种情形），
只抄写不推断，找不到类别词就返回失败；
6. 全部失败 → method=failed，不产生任何伪造字段。
jsonvalid（能否解析出 JSON 对象）与 schemavalid（字段是否合规）分开统计，
便于区分"格式失败"与"内容错误"。
## 4.4 src/vision_client.py —— API 客户端
统一 OpenAI 兼容协议；buildmessages 生成 imageurl + text 双块；
错误分类：401/403/400 不重试（重试无意义），408/429/5xx/超时/连接错误
指数退避重试（尊重 Retry-After，上限 30–60s）；
私有参数（智谱 thinking）若被服务端拒绝，自动去掉后重试一次并记录；
令牌桶限流（默认 1 QPS），线程安全；
返回 ModelResponse，失败也返回对象而不是抛异常，便于逐条落盘。
## 4.5 src/experiment_runner.py —— 批量编排
ThreadPoolExecutor 并发；每线程复用 session（threading.local）；
逐条 append + flush + fsync，进程崩溃后可按 (sample_id, variant) 续跑；
maxcalls 硬闸：达到上限后取消剩余任务，并在摘要中报告 naborted 与停止原因；
记录 24 个字段（见 §6.2），含模型原始返回 raw_text 以便审计；
失败样本照样落盘，不会被静默丢弃。
## 4.6 src/evaluation.py —— 指标
口径写死在文件头注释里，并由单元测试逐项校验：
| 指标 | 分母 |
|---|---|
| 调用失败率 | 全部记录 |
| JSON 有效率 | 全部记录（需 jsonvalid && schemavalid） |
| 无法判断比例 | 成功调用数 |
| Accuracy（有效） | 成功 且抽出了合法类别的样本 |
| Accuracy（严格） | 全部记录（拒答/失败算错） |
| 每类 Precision / Recall / F1 | 有效分类子集 |
| recall_strict | 该类全部样本（含拒答） |
| Macro-F1 | 四类 F1 等权平均 |
| 延迟 mean / median / p95 | 成功调用（最近秩法） |
关键口径：分类得分不要求 Schema 合规。A/B 组是自然语言输出、C 组是严格 JSON；
如果把"Schema 合规"作为得分前提，A/B 的分类能力就完全无法比较，
格式劣势会被误记为识别能力劣势。因此两者分开统计——格式由"JSON 有效率"衡量，
正确性由 Accuracy/Macro-F1 衡量。这一口径由单元测试锁定。
## 5. 多模态 API 接入方式
要点：
图片以 Base64 Data URI 内联，不依赖公网 URL，避免图床上传与隐私问题；
送入前统一缩放到长边 512px，估算单图 ≈258 视觉 Token（32×32 px/Token）；
thinking=disabled 关闭思考链，降低延迟与输出 Token；
视觉接口没有原生 JSON Schema 约束，因此采用"提示词强制 + 本地校验"，
并把 JSON 有效率作为被评测的指标而不是前提假设。
## 6. 提示词管理与结构化输出
## 6.1 三组提示词
| 组 | 文件 | 特征 | 字符数 | SHA256 前 8 位 |
|---|---|---|---:|---|
| A | prompts/prompt_a.txt | 只给任务、类别列表与简短输出要求 | 124 | 098f7653 |
| B | prompts/prompt_b.txt | 增加各类定义、易混淆区分规则、只依据可见信息 | 484 | 914878c3 |
| C | prompts/prompt_c.txt | 再增加严格 JSON 字段、只允许 5 个取值、允许拒答、禁止虚构 | 946 | e5c513d4 |
SHA256 在每次运行前重算并写入原始记录与实验元数据，保证报告引用的提示词
与实际调用完全一致（可追溯）。
## 6.2 逐样本记录字段
字段覆盖需求 6.5 建议的全部字段，并补充 schema_valid（区分解析与校验）、
promptsha256（提示词可追溯）、rawtext（原始响应审计）。
## 7. 异常处理与数据安全
| 场景 | 处理 |
|---|---|
| 无密钥 | 界面/脚本给出中文提示并停止；绝不返回假结果 |
| 401/403 | 不重试，提示检查密钥 |
| 429 | 退避重试并提示可降低 QPS/并发 |
| 5xx / 超时 / 连接错误 | 指数退避重试（默认 3 次） |
| 返回空内容 | 记为失败，不编造 |
| 非 JSON 返回 | 三级降级解析；仍失败则记失败并保留原文 |
| 字段非法/类别越界 | Schema 判非法，predicted_label 留空 |
| 图片损坏/过小/超长宽比 | 上传前拦截，中文报错，且不发起 API 调用 |
| 调用失败 | 保留失败记录并计入失败率 |
| 磁盘写入 | 逐条 append + fsync；CSV 使用 utf-8-sig 保证 Excel 不乱码 |
| 密钥泄漏 | 密钥只从环境/.env 读取；.env 在 .gitignore；日志不打印密钥 |
数据安全：图片会发送至所选服务商处理，README 与界面横幅均有提示；
仅使用公开且许可允许的数据集（CC BY 4.0）。
## 8. 系统实现与界面
单页界面：深色主题，左侧上传区 + 提示词下拉，右侧结果面板；
结果面板展示：姿态（中英）、可见体态描述、不确定性及原因、调用状态、
HTTP 码、模型耗时与含上传的总耗时、Token 用量、图片尺寸变化与视觉 Token 估算、
提示词方案与 SHA256 前缀、模型原始返回（可展开）；
状态徽章：调用成功/失败、Schema 通过/未通过、JSON 有效/无效、存在不确定性；
顶部横幅常驻说明当前服务商与"图片将发送至该服务商"；
无 CDN 依赖，全部资源内联，可离线加载页面。

## 9.3 真实 API 集成验证（非模拟）
| 项 | 结果 |
|---|---|
| 阶段一验证 scripts/verifyapi.py --count 8 | 8/8 成功，原始响应存于 results/verification/verifyC20261019130234.json |
| 端点鉴权 | HTTP 200，鉴权通过 |
| 正式实验 | 600 次调用，0 失败，耗时 26.1 分钟，共 388,407 Token |
| 结果可复现 | plotresults.py 从原始 CSV 重算，指标与首次计算逐字段一致** |
| 故障注入（模拟测试） | 401/403 不重试、429 退避后成功、5xx/超时按策略失败、坏 JSON 走降级 — 全部符合预期 |
解析链路上真实遇到过的两种模型行为，均已覆盖并修复：
1. 思考型输出：模型返回 <think>推理</think><answer>结论</answer>，
推理中常出现与结论相反或半截的类别词 → 解析前剥离 <think>，优先解析 <answer>；
2. 类别词写法漂移：模型把 lying_lateral 写成 lying lateral 或 lying-other
→ 正则允许空格/连字符并归一化。
第 2 点曾导致 A 组 8 条被判"无法解析"。修正后新增 scripts/reparse_results.py，
可在不重新调用 API 的前提下，对已有原始记录重新抽取字段并重算指标
（原始 raw_text 不改动，输入输出文件分离，改动幅度会打印出来供核对）。
本项目实际重解析后可用样本从 590/600 提升到 599/600。
## 9.4 其他工程验证
数据集确定性：在 PYTHONHASHSEED=0/12345/999 下重复构建，
manifest.csv 的 SHA256 完全一致（846AE422…）；
一致性校验：磁盘裁切图数量与清单行数一致（309 = 309）；
中文渲染：matplotlib 用微软雅黑出图，中文标题/坐标轴无乱码；
编码兼容：CSV 统一 utf-8-sig，openpyxl 回读中文正确；
结果口径锁定：分类得分不依赖 Schema 合规（否则 A/B 组无法比较），
该口径由 test_evaluation.py 的用例固定，防止将来被无意改回。

## 11. 项目局限性与后续改进
详见 docs/limitations.md 与 docs/experiment_report.md。要点：
1. 实测准确率仅 33%–38%（四分类随机水平 25%），不足以支撑生产使用；
2. 增加提示词约束改善了格式（JSON 有效率 0% → 99.5%），但没有提升准确率；
3. 模型的拒答机制在提示词层面完全未被触发（0/600），格式可控、可靠性不可控；
4. 测试集 200 条、sitting 仅 13 条，少数类指标方差大；
5. 输入是人工 bbox 裁切的单猪俯视图，不可与整帧多目标任务指标直接比较；
6. 单一模型、单次运行，未做重复实验与置信区间；
3. 单一模型、单次运行，未做稳定性重复（可用 --repeats 开启）；
4. 仅覆盖 2 个猪栏 8 台相机，跨场泛化未验证；
5. Python 3.9 与需求建议的 3.10+ 存在差异，已记录；
6. 后续：unseen-VP 划分泛化实验、sitting 过采样或自助法置信区间、
标注一致性 κ、多模型对照。
